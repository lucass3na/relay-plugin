# relay

A Claude Code plugin that relays I/O-heavy work to a cheap headless Claude model,
saving tokens on large file reads and boilerplate generation. It's a self-hosted
alternative to [`shunt`](https://github.com/spotify/portal-ai-plugins) — same
three-layer strategy, but the transport is `claude -p` instead of a Portal/AiKA call,
so it needs no extra infrastructure: just Claude Code itself.

## How it works

Three layers, from hard gate to soft suggestion:

1. **Hooks** block Claude from reading large files and redirect to the bulk-reader skill
2. **Scripts** handle the `claude -p` invocation and output cleanup
3. **Skills** tell Claude when and how to call the scripts

Claude never assembles bash pipelines from prose. It calls a script with named
arguments. The scripts handle everything internally.

Delegation goes straight through the `claude` CLI's own headless mode (`claude -p`) —
no separate API key, no external service. It reuses whatever auth Claude Code already
has on the machine, calling a cheap model (Haiku by default) with a short, purpose-built
system prompt instead of Claude Code's own ~6.4k-token agent prompt.

## Prerequisites

- [`jq`](https://jqlang.org) — `brew install jq`
- The `claude` CLI on `PATH`, already authenticated (it is, if you're reading this
  inside a Claude Code session)
- Optional: `timeout` or `gtimeout` (Homebrew `coreutils`) so `RELAY_TIMEOUT_SECONDS`
  is actually enforced. Without either, calls run unbounded.

## Installation

```bash
claude plugin marketplace add lucass3na/relay-plugin
claude plugin install relay@lucass3na
```

The repo is public, so anyone can run this without needing access granted first.

Installing from a local checkout instead of GitHub works the same way, just point at
the path:

```bash
claude plugin marketplace add /path/to/relay-plugin
claude plugin install relay@lucass3na
```

Either way, start a new Claude Code session afterward — plugins load at startup, not
mid-session. This works identically in the terminal CLI, the VS Code / JetBrains
extensions, and the desktop app, since they all share the same `~/.claude` plugin
config. One VS Code–specific gotcha: the delegation scripts shell out to the `claude`
binary, and a GUI-launched extension process doesn't always inherit the same `PATH` as
your terminal — if you hit `missing required command: claude` there, it's a `PATH`
issue, not a broken install.

To confirm it installed correctly:

```bash
claude plugin list
```

should show `relay@lucass3na` as `enabled`.

## Scripts

### bulk-read

Delegates file reading to the worker model. Files are wrapped in XML tags
(`<file path="...">`) for clear boundaries, and streamed over stdin — no `ARG_MAX`
ceiling the way argv-based transports have.

```bash
bulk-read --question "What does this service do?" --paths src/Service.java src/Handler.java

# Follow-up: ask again with the same paths
bulk-read --question "Which methods call the database?" --paths src/Service.java src/Handler.java
```

### code-write

Delegates boilerplate generation. Strips markdown fences from output. Can write
directly to disk via `--target`. `--reference` is required — without a file to match
patterns against, the worker would generate context-free code that fits nothing in the
project.

```bash
# Generate and write to file
code-write --spec "Write tests for UserService" --reference tests/OrderTest.ts --target tests/UserTest.ts

# Build on what was just generated by referencing it
code-write --spec "Now add edge case tests" --reference tests/UserTest.ts --target tests/UserEdgeCases.ts

# Output to stdout
code-write --spec "Generate a config stub" --reference config/existing.yaml
```

### One shot per call

Every `claude -p` invocation is `--no-session-persistence`: nothing is kept, and the
caller never resumes a prior turn. Replaying a file corpus is the exact cost this
plugin exists to avoid, so relay does not do it — every call stands alone. Re-sending
files is nearly free where it matters, because the corpus goes to the worker model and
never enters Claude's own context.

## Hooks

### check-file-size (Read hook)

Fires on every `Read` tool call. Blocks full-file reads on files exceeding `MIN_LINES`
(default: 350, configurable via `RELAY_MIN_LINES`). Allows through:
- Targeted reads (offset or limit set)
- Files under the threshold
- Nonexistent files (let Read handle the error)

### check-bash-read (Bash hook)

Fires on every `Bash` tool call. Catches `cat`, `head`, `tail`, `less`, `more` on large
files. Allows through:
- Piped commands (`cat file | grep`) — targeted reads
- Redirections (`cat file > out`) — not reading into context
- Commands with flags that indicate targeted reads
- Non-read commands (`git status`, `grep`, etc.)

## Configuration

All settings are environment variables — add them to the `env` block in
`.claude/settings.json`.

| Variable | Default | Purpose |
|----------|---------|---------|
| `RELAY_MIN_LINES` | `350` | Line count above which the Read/Bash hooks block and redirect |
| `RELAY_MODEL` | `claude-haiku-4-5-20251001` | Model passed to `claude -p` for delegated calls |
| `RELAY_EFFORT` | `low` | `--effort` passed to `claude -p` (low/medium/high/xhigh/max) |
| `RELAY_TIMEOUT_SECONDS` | `180` | Timeout for one delegated call, enforced via `timeout`/`gtimeout` if present |
| `RELAY_MAX_INPUT_CHARS` | `600000` | Soft sanity ceiling on corpus size before invoking |

## What doesn't get delegated

The plugin is designed to know when NOT to delegate:
- **Debugging** — requires Claude's reasoning, not a summary
- **Editing** — Claude needs exact content in context; use targeted reads (offset/limit)
- **Small files** — delegation overhead exceeds savings under 350 lines
- **Architectural decisions** — judgment calls stay on Claude

## Evals

```bash
bash evals/run.sh              # hooks + transport (stubbed claude, no live calls)
bash evals/run.sh --hooks      # hook routing only
bash evals/run.sh --transport  # transport plumbing only
```

## Known limitations

- **No enforcement for code-writer** — only bulk-reader has hook enforcement.
  code-writer relies on Claude recognizing when to use it via the skill description.
- **Timeout enforcement is best-effort** — `RELAY_TIMEOUT_SECONDS` only applies when
  `timeout` or `gtimeout` is on `PATH`. Stock macOS ships neither; `brew install
  coreutils` provides `gtimeout`.
- **Delegated calls still cost something** — this routes to a cheap model instead of
  reading the file into Claude's own context, it doesn't make the read free. Each call
  prints its actual cost (from `claude -p`'s own `total_cost_usd`) to stderr.
- **Extended thinking on the worker** — Haiku may spend a handful of thinking tokens
  even with `--effort low`; this is priced into the reported cost, not hidden.
